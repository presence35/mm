Photos: capture, compress, upload.

Closes the last functional gap. Photos are online-only by decision, and that
is now enforced rather than documented.

server/photos.js   The row is written through the same metadata rules as every
                   other entity and lands in the change log, so a photo reaches
                   other devices by delta pull instead of being invisible to
                   sync.
server/index.js    POST /api/photos, authenticated, 12 MB cap, type allow-list.

src/engines/media/photos.js
                   Capture, canvas downscale to 1600px, JPEG at 0.82, GPS when
                   available, multipart upload. No HEIC dependency: iOS Safari
                   decodes HEIC through an img element and Android hands us
                   JPEG, so canvas covers both. A browser that cannot decode
                   says so plainly rather than uploading a silent failure.

The camera stays usable offline. A worker must never lose the ability to look
at a boat. What fails offline is the upload, and the shutter produces an
explicit blocked state with a reason and a retry, worded so it cannot be
mistaken for a saved photo.

37 tests. New ones cover a photo landing with metadata and reaching the change
log, and an upload for a card that does not exist being refused.

Two notes on my own work: my first tests passed a database into createServer,
which skips bootstrap, so there was no admin to sign in as and the upload
returned 401 - the tests were wrong, not the auth. And the offline note was
missing from the empty photo state; only the populated branch had it.

Not verified end to end: the browser harness served stale modules for most of
this session, so the upload itself was exercised by the server tests rather
than through a real camera.
